## 5. ACID & 崩溃恢复验证

### 5.1 单语句原子性（autocommit）

**关键测试** (`tests/integration/test_autocommit.py`)：

- `test_failed_insert_auto_rolls_back` — 多行 INSERT 中途失败，**整个语句**回滚，无 partial state
- `test_drop_table_rolls_back_on_failure` — DROP 失败恢复后表仍存在
- `test_pk_violation_does_not_leak_partial_data` — PK 冲突中所有行被丢弃

### 5.2 WAL 耐久性

- `tests/integration/test_acid.py` — COMMIT 后 `fsync`，power loss 不会丢失已提交事务
- `tests/integration/test_crash_recovery.py` — open 时检测 `*.wal` sidecar，启动 `Recovery.replay`
- `tests/integration/test_recovery_fuzz.py` — fuzz：随机 kill -9 模拟后验证 replay 一致

### 5.3 B+tree 在事务中

- `tests/integration/test_btree_in_transaction.py` — 事务内 split/merge，rollback 时索引页正确释放
- `tests/integration/test_ddl_in_transaction.py` — DDL 在事务中：CREATE/DROP 在 COMMIT 后生效，ROLLBACK 后消失

### 5.4 异常捕获保证

```python
try:
    db.execute("INSERT INTO t(id) VALUES (2**40)")  # INT overflow
except tinydb.errors.CodecError as e:
    assert "INT out of range" in str(e)
```

→ 所有列类型边界失败都进入同一条 `except CodecError` 分支。

## 10. v0.1.1 修复清单（闭合 codec-exception-consistency 合约缺口）

v0.1.1 是一次 review-driven followup，针对 `codec-exception-consistency` change（合并于 `66086ac`）未能完整闭合 codec 异常合约的 7 处缺口。**+43 / −38 across 5 files，commit `a17eea3`**。

| 缺口 | 修复 | 影响 |
|---|---|---|
| 7 个 codec 的 `encode_py` 仍泄漏 `AttributeError` / `TypeError` / `OverflowError`（Text/Bool/Varchar/Char/Decimal/Date/Time/Timestamp） | 所有 15 个 codec 的 `encode_py` 现在第一行调用 `self.validate(value)` | 任何直接 codec 调用都通过 `CodecError` 收敛 |
| `_DecimalCodec._to_scaled` 抛裸 `OverflowError`（不是 `CodecError`） | 改为抛 `CodecError` | `DECIMAL` 精度溢出 + scaled 溢出都走统一合约 |
| `_VarcharCodec._check` 和 `.validate` 错误消息硬编码 'VARCHAR' | 改为 `self.name` | `CHAR(N)` 列插入超长字符串时显示 `CHAR(5) length 6 exceeds max`，不再是误报的 `VARCHAR(5)` |
| `_TimeCodec.encode_py` 越界抛 `ValueError` | 改为 `CodecError` | 时间字段越界统一收口 |
| `executor.py:1324` 索引路径 `except CodecError: ref=None` 静默吞无效 WHERE 字面量 | 移除整个 `try/except CodecError` | `WHERE id = 2147483648` 在 `INT PRIMARY KEY` 上恢复 pre-change `OverflowError` 行为（抛 `CodecError` 而非静默 `[]`） |
| `Catalog.create_table` isinstance guard 处于错层（仅 1/3 TableInfo 构造点受保护） | 移入 `TableInfo.__post_init__`；3 个构造点（`create_table` / `from_bytes` / `_unpack_chain`）统一受保护；create_table 简化为单行 `tuple(schema)` | catalog 类型校验在类型系统层而非 ingress 层 |
| `parse_bool_literal` 死代码 | 删除 | tokenizer 内联 + `_BoolCodec.parse_literal` 复制了相同 body；模块级函数无任何 src/ caller |
| 测试合约 `pytest.raises(OverflowError)` 锁定多继承 shim | 改为 `pytest.raises(CodecError)` | 4 处测试（SMALLINT/BIGINT/DECIMAL precision/DECIMAL scaled）现在真正锁定新合约，未来移除多继承 shim 时不会误导 |

**跳过项**：review 角度标记为 PLAUSIBLE 的"INT/FLOAT 在 INSERT 热路径上有双 validate"——属于给非预校验 caller 的 deliberate safety net，影响小，保留。
